# Сначала документация, потом код

## Жёсткое правило: API и внутренности — только через MCP-документацию

Перед тем как исследовать исходники библиотеки, читать её код, угадывать API
или писать код с использованием сторонней библиотеки, фреймворка, SDK или
сервиса, ты ОБЯЗАН сначала получить официальную документацию через MCP.
Изучение кода библиотеки без предварительной сверки с документацией запрещено.

Доступны два взаимодополняющих сервера:

| сервер     | для чего                                                                    | инструменты                                                          |
|------------|-----------------------------------------------------------------------------|----------------------------------------------------------------------|
| `web-docs` | сведения по API: пакеты, официальные страницы, примеры использования         | `list_docs`, `search_docs`, `lib_docs`, `fetch_url`, `web_search`    |
| `deepwiki` | глубокий анализ GitHub-репозитория: архитектура, внутренности, «почему так» | `read_wiki_structure`, `read_wiki_contents`, `ask_wiki_question`     |

DeepWiki не умеет искать по имени пакета — ему нужен `owner/repo`. Имя пакета
резолвит `web-docs`: `lib_docs` возвращает поле `repository`, которое и служит
мостом к DeepWiki.

## Обязательный порядок

1. Определи, что известно:
   - имя пакета/сервиса → `lib_docs` (`ecosystem`: `npm`/`pypi`/`crates`/`go`/`github`,
     по умолчанию `auto`);
   - язык/API без пакета (`Array.prototype.map`, `asyncio.gather`) →
     `search_docs` (`target`: `mdn`, `python`, `nodejs`, …);
   - уже есть URL → сразу `fetch_url`;
   - ничего не известно → `web_search`, затем `fetch_url` по официальному домену.
2. Перед походом в сеть проверь локальный кэш: `list_docs` (без аргументов —
   индекс, с `query` — поиск, с `path` — полный текст). `search_docs` и
   `lib_docs` тоже сначала смотрят в `docs/`.
3. Получил `owner/repo`, и нужен разбор архитектуры, а не только README:
   `read_wiki_structure` → `read_wiki_contents` → точечный `ask_wiki_question`.
4. Только после этого, при необходимости, переходи к чтению и анализу кода.
5. Если ни `web-docs`, ни `deepwiki` не дали ответа — явно сообщи об этом,
   и лишь затем углубляйся в исходники.

## Роутинг

- «Как называется функция/флаг/опция в пакете X» → `lib_docs`, затем
  `fetch_url` на официальную страницу. Не DeepWiki: он отдаёт пересказ, а не
  точную сигнатуру.
- «Как устроен проект X, где точка расширения, как работает пайплайн» →
  DeepWiki.
- «Какая актуальная версия и как мигрировать» → `lib_docs` с `version`/`refresh`,
  затем `fetch_url` на changelog/upgrade guide.
- Не доверяй устаревшему локальному кэшу: `lib_docs(refresh: true)` или
  `search_docs(skip_local: true)`, если есть подозрение, что документ старый.
- DeepWiki работает только с публичными GitHub-репозиториями. Для закрытых
  репозиториев, не-GitHub проектов и внутренних сервисов — официальная
  документация через `web-docs`.

## При включённом Code Mode

Инструменты вызываются внутри `execute`:

- `tools["web-docs"].lib_docs({...})`, `tools["web-docs"].search_docs({...})`,
  `tools["web-docs"].fetch_url({...})`, `tools["web-docs"].web_search({...})`,
  `tools["web-docs"].list_docs({...})`;
- `tools.deepwiki.read_wiki_structure({...})`,
  `tools.deepwiki.read_wiki_contents({...})`,
  `tools.deepwiki.ask_wiki_question({...})`.

Не полагайся на память модели для API сторонних библиотек — всегда сверяйся
через эти серверы.

## Ограничения

- `deepwiki` не требует авторизации, но подчиняется лимитам сервиса;
  `ask_wiki_question` принимает до 10 репозиториев за вызов.
- `web_search` идёт через DuckDuckGo HTML и может упираться в rate limit —
  в этом случае используй `fetch_url` по известному URL.
- Скачанные документы складываются в `~/.local/share/web-docs-mcp/docs`
  (не в репозиторий); кэш — в `~/.cache/web-docs-mcp`.
