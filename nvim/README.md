# Neovim

Конфиг рассчитан на Neovim 0.13+ (используются `vim.pack`, встроенное
автодополнение, мультикурсоры). Плагины ставятся менеджером `vim.pack`:
список — в `lua/plugins.lua`, установка происходит при старте, версии
фиксируются в `nvim-pack-lock.json` (в git не попадает).

```sh
:checkhealth vim.pack   # состояние плагинов
:packupdate             # обновить плагины (интерактивно)
:packdel имя            # удалить неактивный плагин
```

## Ревью изменений перед коммитом

Три уровня, от мелкого к крупному.

### 1. В процессе правки — gitsigns

В `signcolumn` видно, что изменено, а что уже застейджено (значки для
индекса отличаются). Маппинги создаются только в буферах git-репозитория.

| Клавиши              | Действие                                        |
| -------------------- | ----------------------------------------------- |
| `]c` / `[c`          | следующий / предыдущий хунк                     |
| `<leader>hp`         | превью хунка в popup                            |
| `<leader>hi`         | превью хунка прямо в буфере                     |
| `<leader>hs` (n/v)   | застейджить хунк / выделенные строки            |
| `<leader>hu`         | отменить stage хунка                            |
| `<leader>hr` (n/v)   | откатить хунк / выделение к индексу             |
| `<leader>hS`         | застейджить весь буфер                          |
| `<leader>hR`         | откатить весь буфер                             |
| `<leader>hd`         | diff буфера против индекса                      |
| `<leader>hD`         | diff буфера против предыдущего коммита (`~`)    |
| `<leader>hb`         | blame строки (полный)                           |
| `<leader>hB`         | включить/выключить blame на курсоре             |
| `<leader>hw`         | word-diff                                       |
| `<leader>hq`         | все хунки в quickfix                            |
| `ih` (в `o` / `x`)   | text-object «хунк»                              |

То же доступно командами: `:Gitsigns stage_hunk`, `:Gitsigns preview_hunk`,
`:Gitsigns diffthis`, `:Gitsigns blame` и т. д.

### 2. Обзор по репозиторию — fzf-lua

| Клавиши        | Действие                                                  |
| -------------- | --------------------------------------------------------- |
| `<leader>gg`   | `git_status`: изменённые файлы + превью                   |
| `<leader>gD`   | **только индекс** — ровно то, что уйдёт в коммит          |
| `<leader>gd`   | всё, что изменилось с `HEAD` (индекс + рабочее дерево)    |
| `<leader>gh`   | `git_hunks`: хунки по файлу/репозиторию                   |
| `<leader>gl`   | история коммитов проекта                                  |
| `<leader>gL`   | история коммитов текущего буфера (с follow по переименованиям) |
| `<leader>gb`   | blame буфера                                              |

В `git_status`: `←` — stage, `→` — unstage, `C-x` — reset, `C-d` — хунки
файла, `C-q` — коммиты.

### 3. Коммит — из терминала

```sh
git commit      # открывает nvim (EDITOR=/usr/bin/nvim)
```

Включён `git config --global commit.verbose true`, поэтому в
`COMMIT_EDITMSG` сразу виден дифф застейдженного. Дополнительно:

| Клавиши        | Действие                                     |
| -------------- | -------------------------------------------- |
| `<leader>gp`   | `:DiffGitCached` — staged-дифф отдельным сплитом |
| `:wq`          | записать сообщение и завершить коммит        |

В буфере коммита включён `spell`; дифф ниже сообщения подсвечивается
встроенным `syntax/gitcommit.vim`.

### Типичный проход

```
]c ]c <leader>hp ...          # пробежаться по своим изменениям
<leader>hs                    # застейджить то, что относится к коммиту
<leader>gD                    # глазами проверить только индекс
git commit                    # сообщение + дифф в одном окне, :wq
```

Если в индекс попало лишнее — `<leader>gg` и `→` (unstage) или
`:Gitsigns reset_hunk` в файле, затем повторный проход по `<leader>gD`.

### Если что-то не так

- Нет значков: файл вне git-репозитория или не застейджен/не отслеживается
  (новые файлы подхватываются благодаря `attach_to_untracked = true`).
- Нет диффа в окне коммита: `git config --get commit.verbose` должен вернуть
  `true`.
- gitsigns собирается под dev-версию Neovim: если после обновления nvim
  появились ошибки, обнови плагин (`:packupdate`) — README плагина прямо
  предупреждает о рассинхроне с мастер-веткой.

## Прочие маппинги

`<leader>` — пробел. Основные группы: `f*` — поиск (fzf-lua), `b*` — буферы,
`t*` — табы, `s*` — сплиты, `h*` — хунки git, `g*` — git, `e` — oil,
`q` / `d` — диагностика LSP, `<leader>hk` — which-key.
