# Neovim

Конфиг рассчитан на Neovim 0.13+ (`vim.pack`, встроенное автодополнение,
мультикурсоры). Плагины ставит `vim.pack`: список — `lua/plugins.lua`,
установка при старте, версии пинятся в `nvim-pack-lock.json` (в git не попадает).

```sh
:checkhealth vim.pack   # состояние плагинов
:packupdate             # обновить (интерактивно)
:packdel имя            # удалить неактивный
```

## Ревью перед коммитом

Четыре уровня, от мелкого к крупному.

**1. По ходу правки — gitsigns.** В `signcolumn` видно изменённое и
застейдженное (значки для индекса отличаются); маппинги создаются только в
буферах git-репозитория.

| клавиши | действие |
|---|---|
| `]c` / `[c` | следующий / предыдущий хунк |
| `<leader>hp`, `<leader>hi` | превью хунка в popup / в буфере |
| `<leader>hs`, `<leader>hu` | застейджить / отменить stage (n, v) |
| `<leader>hr` | откатить хунк к индексу (n, v) |
| `<leader>hd`, `<leader>hD` | diff против индекса / против `HEAD~` |
| `<leader>hb`, `<leader>hB` | blame строки / переключатель blame |
| `<leader>hq` | все хунки в quickfix |
| `ih` (в `o` / `x`) | text-object «хунк» |

Остальное — `:Gitsigns stage_hunk|preview_hunk|diffthis|blame` и `:help gitsigns`.

**2. Обзор по репозиторию — fzf-lua.**

| клавиши | действие |
|---|---|
| `<leader>gg` | `git_status` с превью |
| `<leader>gD` | **только индекс** — ровно то, что уйдёт в коммит |
| `<leader>gd` | всё, что изменилось с `HEAD` |
| `<leader>gh` | хунки по файлу/репозиторию |
| `<leader>gl`, `<leader>gL` | история проекта / буфера (с follow переименований) |
| `<leader>gb` | blame буфера |

В `git_status`: `←` stage, `→` unstage, `C-x` reset, `C-d` хунки файла, `C-q`
коммиты.

**3. Вся ветка целиком — diffview.**

| клавиши | действие |
|---|---|
| `<leader>gm` | ревью ветки: панель файлов + диффы в отдельном табе |
| `<leader>gM` | коммиты ветки от той же точки (`DiffviewFileHistory`) |

Открывает `:DiffviewOpen <merge-base>`, где merge-base — точка ответвления
текущей ветки от базовой (`origin/HEAD`, иначе перебор `origin/main`,
`origin/master`, `main`, `master`). Именно merge-base, а не кончик `main`:
чужие коммиты, приехавшие в базовую ветку после ответвления, в ревью не
попадают. База — SHA, поэтому в дифф входит и незакоммиченное рабочее дерево.

Внутри: `<Tab>` / `<S-Tab>` — следующий / предыдущий файл, `<CR>` / `o` — дифф
файла, `<leader>e` — в панель файлов, `<leader>b` — скрыть/показать панель,
`s` / `-` — stage / unstage файла, `S` / `U` — stage / unstage всех, `X` —
откатить файл, `i` — дерево/список, `g<C-x>` — сменить layout, `]x` / `[x` и
`<leader>co|ct|cb|ca` — конфликты при merge/rebase, `g?` — помощь по клавишам.
Закрыть: `:DiffviewClose` или `:tabclose` (`q` — только в служебных панелях).
`<leader>gM` открывает `:DiffviewFileHistory --range=<merge-base>..HEAD` — те же
границы, но только коммиты ветки.

**4. Коммит.** `git commit` открывает nvim (`EDITOR=/usr/bin/nvim`), а
`commit.verbose=true` показывает дифф застейдженного прямо в `COMMIT_EDITMSG`.
`<leader>gp` — `:DiffGitCached` отдельным сплитом, `:wq` — записать и закрыть.
Включён `spell`, дифф подсвечен `syntax/gitcommit.vim`.

```text
]c ]c <leader>hp ...   # пробежаться по своим изменениям
<leader>hs             # застейджить то, что относится к коммиту
<leader>gD             # глазами проверить индекс
git commit             # сообщение + дифф, :wq
```

Если в индекс попало лишнее: `<leader>gg` и `→`, либо
`:Gitsigns reset_hunk`, затем снова `<leader>gD`.

Если что-то не так: нет значков — файл вне git (новые подхватывает
`attach_to_untracked`); нет диффа в коммите — `git config --get commit.verbose`
должен вернуть `true`; ошибки после обновления nvim — gitsigns собирается под
dev-версию, обнови плагин (`:packupdate`).

## Автодополнение

В буферах с LSP меню открывается само при наборе (задержка 10 мс) и после точки
`.` Ничего не выбрано заранее: `<Tab>` / `<C-n>` — следующий, `<C-y>` — принять,
`<C-e>` — закрыть, `<CR>` остаётся переводом строки. Источник только LSP, слов из
буфера нет; по требованию — `<C-x><C-n>`. Без LSP автодополнения нет,
`<C-Space>` / `<C-n>` работают как раньше.

## Прочие маппинги

`<leader>` — пробел. Группы: `f*` — поиск (fzf-lua), `b*` — буферы, `t*` —
табы, `s*` — сплиты, `h*` — хунки git, `g*` — git, `e` — oil, `q` / `d` —
диагностика LSP, `<leader>hk` — which-key.
